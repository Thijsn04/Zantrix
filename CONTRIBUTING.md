# Contributing to Zantrix

The project is in requirements discovery and architecture design. Read the [documentation](docs/README.md), [decisions](docs/decisions.md), [open questions](docs/open-questions.md) and [repository instructions](AGENTS.md) first. Discuss substantial scope before starting product code; detailed implementation plans have not been approved.

Use English for documentation, code, identifiers, comments and commit messages. Preserve the difference between accepted requirements, provisional preferences, proposals and implementation evidence. Explain why a change is needed, its boundaries and how it was checked. Link relevant decisions and identify remaining uncertainty.

For this documentation-only baseline, verify relative links and anchors, Markdown formatting, terminology, statuses and `git diff --check`. There is no replacement application build or test suite yet. Do not restore the old setup to manufacture a passing check. Exact tools and version policies remain open.

Use synthetic information only. Do not publish credentials or patient data. Follow the [security policy](SECURITY.md) for suspected vulnerabilities and the [code of conduct](CODE_OF_CONDUCT.md) when participating.

The existing [AGPL v3 license](LICENSE) is preserved. External-module licensing and distribution rules remain to be designed; do not infer permission for a specific proprietary distribution model.
